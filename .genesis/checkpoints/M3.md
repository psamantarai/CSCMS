## Quiz-me gate (Q+A block) · 2026-08-08
1. **Design decision** — "What data characteristic ruled out `@tanstack/react-table`, and what was
   built instead?" → **Answer:** each page's `useQuery` already fetches the full array for the current
   page/filter client-side, so no server-side sort/virtualization is needed — a small shared `useSort`
   hook (`Array.sort()` over the already-loaded array) + `SortableTableHead` wrapper around the
   existing `TableHead` is sufficient, per PLAN.md 9.6's own reasoning.
2. **Edge case** — "Click the same header three times — what's the state after each click?" →
   **Answer:** click 1 → `{key, dir:"asc"}` (ascending); click 2 (same key) → `{key, dir:"desc"}`
   (descending); click 3 (same key) → `null` (unsorted — table reverts to original fetch order, icon
   disappears). Verified live in-browser on Transactions.tsx (`#7..#1` → `#1..#7` → back to `#7..#1`).
3. **Change impact** — "Banking's Customer column sorts by `t.customer_id ?? -1` — what does the cell
   actually show, and why does that still match on-screen order?" → **Answer:** the cell renders
   `#{t.customer_id}` (or "—" when null); sorting numerically by the raw `customer_id` produces the
   same order as sorting the displayed `#N` labels would, since the numeric and string-label orderings
   coincide for this `#`-prefixed integer format — visually consistent even though it isn't sorting by
   a resolved customer name.
- Verdict: **APPROVE** (3/3 correct)
