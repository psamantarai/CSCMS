1 · The Locked Spec (what we are building)

Cognitive job: CSCMS is a plain (non-AI) FastAPI + React + SQLite ledger/shop-management app — genesis is not making the product agentic, it's making work on this repo loop-ready. The job: carry docs/PLAN.md's remaining phases (9.5.15 dark mode → 9.5.16 sweep → Phase 10 Electron packaging → Phase 11 on request) to completion, one milestone at a time, each verified against its own already-written Verify: line, never touching the ledger's money-writing path.

Inputs: a docs/PLAN.md step + its Verify line, current src//backend/ state, context-graph.json invariants  →  Outputs: a diff satisfying that step's Verify line, plus a docs/progress-tracker.html update

Autonomy level: scoped, not full — L1 BUILD/L4 VERIFY may iterate un-prompted inside one PLAN.md step, but the loop stops and reports back at every step boundary. CLAUDE.md's "Plan Execution Workflow" (stop after each step, wait for the user) overrides genesis's default full-milestone autonomy; G6 was deliberately not run this session — see checkpoints/CURRENT.md.  |  Human-in-the-loop points: end of every PLAN.md step (mandatory stop); before Phase 10 work touches installer/process lifecycle; before any Phase 11 item is pulled forward (only on explicit request, per PLAN.md itself).

Failure tolerance: zero on the three money invariants in context-graph.json (single_money_source, integer_paise, checked_write_isolation) — any violation blocks the milestone regardless of how the UI looks. Cosmetic/dark-mode regressions are recoverable within the loop, not blocking.  |  Trust boundary: single local operator, single machine, no network exposure beyond localhost FastAPI↔Electron (PLAN.md's "single operator, single machine" — noted in the Risk notes as an assumption that does not hold for concurrency, only for network trust). The ledger and the Phase 8 auth/audit layer are the actual trust boundary, not external actors.

2 · Definition of Done (binary gates — checked by the VERIFIER, not the maker)

CSCMS has no LLM/agent/RAG/distributed components, so the orchestrator's AI-specific gates (schema-validated model outputs, prompt-injection threat model) don't apply and are dropped rather than force-fit. These are the gates that do apply, translated from the relevant agentic-swe-master phases and Cross-Domain Core Rules.

Presentation-only diffs never touch lib/api.ts, lib/queries.ts, lib/format.ts, or a mutation body while Phase 9.5 is active (Rule 3 — test at the boundary; context-graph invariant phase_9.5_presentation_only)
No stored balance column reintroduced; every balance stays SELECT SUM(amount_paise) FROM ledger (ARCHITECTURE.md §2; invariant single_money_source)
Ledger rows stay immutable and append-only; corrections are reversing entries, never UPDATE/DELETE (Phase 15/11 audit-trail gate, adapted — "append-only and tamper-evident")
Any check-then-write on ledger state runs inside BEGIN IMMEDIATE, not a bare SELECT then write (Phase 12 Reliability gate — idempotent retries; invariant checked_write_isolation, PLAN.md H.1/H.11)
Electron backend child process has a clean spawn/terminate — no orphaned process on quit or crash (Phase 13 Infrastructure gate, adapted from PLAN.md 10.2 Verify)
npx tsc --noEmit clean AND pnpm build succeeds
One verify pass by a separate agent/model (L4)
No context-graph.json invariant violated by the change

A milestone is DONE only when every box above is checked by the verifier, never the maker.
